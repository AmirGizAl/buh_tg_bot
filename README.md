# Бухгалтерский Telegram-бот (buh_tg_bot)

Бот для учёта движения денежных средств по нескольким мультивалютным счетам (RUB, USD, EUR), с ролями **Owner** и **Employee**, откатом ошибочных транзакций, сверкой (закрытием периода) и выгрузкой отчётов в Excel/CSV.

## Стек

- Python 3.12, [aiogram 3](https://docs.aiogram.dev/) (FSM, inline-клавиатуры)
- SQLite (SQLAlchemy async + aiosqlite)
- openpyxl для `.xlsx`-отчётов, стандартный `csv` для `.csv`
- Docker / docker-compose для деплоя

## 1. Создать бота и рабочую группу

1. В Telegram откройте **@BotFather** → `/newbot` → следуйте инструкциям → скопируйте токен (`123456789:AA...`). Это `BOT_TOKEN`.
2. Создайте рабочую **группу** в Telegram — сюда будут дублироваться все уведомления бота.
3. Добавьте бота в группу и сделайте его **администратором** (нужно для надёжной работы с сообщениями и для автоматического выхода из чужих групп).
4. Узнайте `chat_id` группы:
   - Напишите любое сообщение в группе.
   - Откройте `https://api.telegram.org/bot<BOT_TOKEN>/getUpdates` в браузере (с реальным токеном).
   - Найдите `"chat":{"id":-100XXXXXXXXXX, ...}` — это отрицательное число и есть `GROUP_CHAT_ID`.
5. Узнайте свой Telegram user id (вы — Owner): напишите боту `/start` в личке один раз (он ответит отказом в доступе, это нормально) и посмотрите `from.id` в логах бота, либо воспользуйтесь ботом вроде @userinfobot.

## 2. Настроить

```bash
cp .env.example .env
```

Заполните `.env`:

```
BOT_TOKEN=123456789:AA...
OWNER_ID=111111111
GROUP_CHAT_ID=-1001234567890
DB_PATH=data/bot.db
```

Дальнейшие сотрудники добавляются уже изнутри бота (см. ниже), а не через `.env`.

## 3. Запуск через Docker

```bash
docker compose up --build -d
```

База SQLite сохраняется на хосте в `./data/bot.db` (примонтированный volume).

Контейнер использует `network_mode: host`, чтобы избежать проблем с DNS/маршрутизацией Docker-сети, которые иначе могут приводить к `TelegramNetworkError: Request timeout error`.

### Если бот вообще не может достучаться до Telegram

Если в логах повторяется `TelegramNetworkError` / таймаут соединения и контейнер постоянно перезапускается — скорее всего, провайдер блокирует `api.telegram.org` напрямую. Проверьте с хоста:

```bash
curl -m 8 -o /dev/null -w "HTTP %{http_code}\n" https://api.telegram.org
```

Если это тоже не проходит, боту нужен прокси. Укажите `PROXY_URL` в `.env`:

```
PROXY_URL=socks5://user:pass@your-proxy-host:1080
```

Затем пересоберите: `docker compose up --build -d`.

#### Использование Hysteria2-прокси

Hysteria2 — не SOCKS/HTTP-прокси-протокол сам по себе, поэтому его нельзя указать напрямую в `PROXY_URL`. Вместо этого (на ветке `ru_version`) `docker-compose.yml` поднимает официальный клиент Hysteria2 как сайдкар (`hysteria` сервис), который открывает локальный SOCKS5-прокси, к которому уже подключается бот:

1. `cp hysteria/config.example.yaml hysteria/config.yaml`
2. Заполните `hysteria/config.yaml` по вашей `hysteria2://` share-ссылке:
   - `hysteria2://AUTH@SERVER:PORT?insecure=1#name` →
     `server: SERVER:PORT`, `auth: AUTH`, `tls.insecure: true` (только если в ссылке был `insecure=1`).
3. Оставьте в `.env` `PROXY_URL=socks5://127.0.0.1:1080` — оба контейнера используют `network_mode: host`, поэтому бот достаёт до локального SOCKS5-порта клиента Hysteria2 через `localhost`.
4. `docker compose up --build -d` (при первом запуске подтянет образ `tobyxdd/hysteria`)

`hysteria/config.yaml` в `.gitignore`, так как содержит реальные данные прокси.

Логи:

```bash
docker compose logs -f
```

Остановить:

```bash
docker compose down
```

## 4. Использование бота

Каждый допущенный пользователь открывает **личный чат** с ботом и отправляет `/start` — бот показывает меню в зависимости от роли (Owner или Employee). Все функциональные действия выполняются в личном чате; в рабочей группе бот только дублирует уведомления о завершённых действиях и не реагирует на обычные сообщения (кроме служебного распознавания username при онбординге сотрудников).

### Owner
- **Приход / Расход** — заявить транзакцию по выбранному счёту, с комментарием; вместо суммы можно ввести арифметическое выражение (например `25+5*3-15/5`).
- **Сверить** — закрыть период по одному счёту или по всем счетам сразу.
- **Отчёт** — бот предлагает выбрать тип: **Текущий** (несверенные транзакции: текстовая таблица в чате + выгрузка в Excel/CSV) или **Сверено** (выгрузка сверенных транзакций за период — сегодня / неделя / месяц / всё время — в Excel или CSV).
- **Создать счёт** — новый счёт в одной из трёх валют (RUB/USD/EUR) с названием.
- **Удалить счёт** — мягкое удаление: счёт пропадает из выбора, но остаётся в истории отчётов. Несверенные транзакции по нему автоматически откатываются, кнопка «Откатить» на них перестаёт быть активной.
- **Допустить сотрудника** — ввести `@username`; доступ откроется, как только этот пользователь впервые напишет боту в личку или что-нибудь в рабочей группе.
- **Удалить сотрудника** — немедленно закрывает доступ.
- **Члены команды** — список активных сотрудников и ожидающих приглашений.

### Employee
- Приход, Расход, Сверить, Отчёт — тот же операционный функционал, что и у Owner, без управления счетами и сотрудниками.
- **Откатить** — под каждым сообщением о собственной транзакции (только в своей личке, только для самого автора) есть кнопка отката, пока транзакция не сверена.

## Структура проекта

```
bot/
  config.py          # env-конфигурация
  main.py             # точка входа
  db/                 # SQLAlchemy-модели + async engine
  services/            # бизнес-логика: счета, транзакции, отчёты, доступ, уведомления в группу
  keyboards/            # reply/inline-клавиатуры
  handlers/             # aiogram-роутеры по фичам
  middlewares/          # доступ: онбординг по username, роли, закрытый контур
```
